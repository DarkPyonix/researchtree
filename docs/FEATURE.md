# Features

기능 명세. 각 항목의 단계(**P0**/**P1**/**P2**)는 [ROADMAP.md](ROADMAP.md)의 단계와 대응한다.

트리와 패널 기능(2~3절)은 세 가지 제공 형태(중앙 웹, VS Code 확장, 로컬 실행)에서 모두 같다. 형태별 차이는 1절과 4~5절에 정리한다.

## 1. 접속과 로그인 (중앙 웹)

### 1.1 최초 로그인 (P0)

- 토큰 없이 접속하면 트리 대신 "GitHub로 로그인" 화면을 보여준다.
- 버튼을 누르면 GitHub 인가 페이지로 이동한다. 승인하고 돌아오면 자동으로 원래 보려던 화면(레포, 노드)으로 복귀한다.
- 요청 scope는 `repo`다. 비공개 레포의 PR을 읽고 쓰기 위해 필요하다.
- 로그인한 사용자의 아바타와 계정 메뉴를 우측 상단에 둔다. 마우스를 올리면 열리고(터치 화면은 눌러서 여닫는다) 상세 패널보다 위에 뜬다. 항목은 이 레포 GitHub에서 열기, 다른 레포 열기, 사용 가이드, ResearchTree 저장소, 로그아웃이다. 로그아웃하면 브라우저에 저장된 토큰을 지운다.
- 401 응답(토큰 만료나 권한 취소)을 받으면 로그인 화면으로 돌아간다.

### 1.2 레포 선택 (P0)

- 주소 `?repo=owner/name`으로 레포를 지정한다.
- 레포가 지정되지 않았으면 레포 선택 화면을 보여준다. 사용자가 접근할 수 있는 레포 가운데 `research` 브랜치가 있는 레포를 목록으로 띄운다. 최근에 본 레포는 위에 둔다.
- 레포에 `research` 브랜치가 없으면 [CONVENTIONS.md](CONVENTIONS.md)로 연결되는 안내를 보여준다.

### 1.2.1 브랜치 설정 (P0)

- 툴바의 "설정"에서 레포마다 루트 브랜치 이름(기본 `research`)과 실험 브랜치 접두사(기본 `experiment/`)를 바꾼다.
- 설정은 호스트 저장소(브라우저, VS Code 상태)에 레포별로 저장되고, 저장하면 트리를 다시 불러온다.
- 루트 브랜치가 없다는 안내 화면에서도 바로 설정을 열 수 있다.
- 학습 스크립트의 `rt.log()`도 레포의 `.researchtree`에서 같은 접두사를 읽는다.

### 1.2.2 언어 (P0)

- 뷰어와 VS Code 확장의 UI는 한국어와 영어를 지원한다. 기본값은 환경 언어다(웹과 로컬은 브라우저 언어, 확장은 VS Code 표시 언어). 환경 언어 목록에 한국어가 있으면 한국어, 아니면 영어다.
- GitHub API는 사용자 로케일을 주지 않고, IP로 지역을 찾으려면 제3자 서비스를 불러야 한다. 그래서 환경 언어를 기본값으로 쓴다.
- 툴바의 "설정" 창 맨 위에 전역 **언어** 항목(자동 / 한국어 / English)을 두고, 그 아래에 레포별 브랜치 설정을 둔다. 언어는 모든 레포에 공통으로 호스트 저장소에 저장한다.
- Python CLI 출력은 한국어와 영어를 지원한다. `RESEARCHTREE_LANG` → `LC_ALL`/`LC_MESSAGES`/`LANG` → 운영체제 표시 언어 순으로 정하고, 한국어가 아니면 영어다. 에이전트용 출력(manifest, 카드, JSON)은 언어와 상관없이 영어다.

### 1.3 공유 링크 (P0)

- 현재 레포와 선택 노드가 주소에 반영된다. 예: `?repo=lab/moshi&node=experiment/depth-lr-half`
- 링크를 받은 사람도 로그인 후 같은 화면을 본다. 해당 레포에 권한이 없으면 권한이 없다는 안내를 보여준다.

## 2. 트리

### 2.1 3D 연구의 섬 (기본 화면, P0)

- 파스텔 톤 복셀 섬을 등각(아이소메트릭) 시점으로 보여준다. research 버전(루트 v1 포함)마다 섬이 따로 있고, 각 노드는 자신이 뻗어 나온 버전의 섬에 놓인다. 섬 사이는 넓은 바다로 떨어뜨린다(다른 섬에 놓이는 형제 사이에 간격을 더 두고, 새 버전은 넓은 물길 뒤에서 시작한다). 섬을 떠나는 길은 기둥 위 나무 나루터로 끝나고, 섬 사이 바다에는 돛과 가지 색 깃발을 단 작은 나룻배가 매여 살짝 흔들린다. 바다 전체를 가로지르는 다리는 없다. `research`는 섬의 큰 고목이고, 가지는 가지 색이 섞인 흙길, 각 실험은 길 끝의 텃밭에 심은 식물이다.
- 식물 모양이 상태를 나타낸다. 채택은 열매와 울타리가 있는 다 자란 나무, 진행 중은 살랑이는 묘목, 기각은 잿빛 그루터기와 떨어진 잎, 초안은 새싹 둔덕이다.
- 노드 위에 흰 라벨 칩(브랜치 이름, 라벨 메트릭 값, 상태)을 띄운다. 계절 단어는 넣지 않는다. 라벨 메트릭은 섬(research 버전)마다 따로 고른다. 버전마다 주로 보는 지표가 다를 수 있기 때문이다. 버전 기념탑(첫 섬은 `research` 고목, 즉 v1)을 눌러 여는 버전 패널의 "라벨 메트릭" 목록에서 고른다. 목록은 그 섬에 기록된 메트릭 키를 많이 쓰인 순서로 보여주고, 기본값은 가장 많이 쓰인 메트릭이며, "표시 안 함"으로 끌 수 있다. 고른 값은 레포별로 기억한다. 칩이나 식물을 누르면 카메라가 날아가고 상세 패널이 열린다. 선택한 노드에는 가지 색 고리가 깜빡인다.
- 처음 열면 세대 순서대로 길이 뻗고 식물이 자라난다. 꽃, 풀, 돌, 덤불, 섬 주변을 흐르는 구름을 장식으로 둔다.
- 드래그로 이동, 오른쪽 드래그로 회전, 휠로 확대한다. 상태 레이어로 가린 실험은 반투명해진다.
- WebGL을 쓸 수 없으면 트리를 그릴 수 없다는 안내를 보여준다.

### 2.1.1 평면 보기 (보조 화면, P0)

- 툴바의 "평면 보기"로 전환한다. 선택 상태는 유지된다.
- 별도 화면이 아니라 같은 3D 장면이다. 카메라가 위에서 내려다보는 시점으로 돌며 식물이 바닥으로 눌리고, 땅·물·나루터·나룻배·장식이 사라져 흙길, 텃밭과 눌린 식물, 버전 돌, 라벨 칩만 페이지의 점무늬 배경 위에 남는다. 바다를 건너는 구간은 점선 길 타일로 그려 가지가 끊기지 않게 한다. "입체 보기"를 누르면 평면에서 섬이 솟아오르며 등각 시점으로 돌아간다(레퍼런스 `docs/references/qr_tree_demo.mp4`).
- 배치, 가지 색, 라벨 칩, 경고 배지는 3D와 같다.
- 드래그로 이동, 휠로 확대만 된다. 회전은 막는다.

### 2.2 상세 패널 (P0)

노드를 클릭하면 오른쪽에 패널이 열린다. 로마 여행 앱의 오른쪽 패널을 참고한다.

- 탭 **내용**: 가설, 변경점, 상태, 결론(마크다운 렌더링, sanitize 필수). **수정** 버튼으로 앱 안에서 고친다. YAML의 가설·변경·상태(자동이면 필드 삭제)·태그·W&B 링크, 그리고 YAML 블록 아래 본문 전체(결론, 메모 등). `metrics`, `parent` 등 다른 필드와 주석, 키 순서는 유지한다. 저장 직전에 PR 본문을 다시 읽어, 불러온 뒤 GitHub에서 바뀌었으면 덮어쓰지 않는다. 나머지 본문은 무손실로 유지한다
- 탭 **협업**: PR 댓글과 코드 리뷰 댓글(마크다운, sanitize)을 시간순으로 보여주고, 댓글을 남긴다(`POST /issues/{n}/comments`)
- 탭 **메트릭**: `metrics` 표. 부모 대비 증감(Δ)을 표시한다
- 탭 **커밋**: 브랜치 커밋 목록과 부모 대비 diff 링크
- 탭 **변경사항**: PR의 Files changed(`/pulls/{n}/files`). 파일별 상태와 +/− 줄 수, 펼치면 unified diff(파일당 400줄까지, 나머지는 GitHub 링크)
- 버튼: "GitHub에서 열기"
- 선택한 노드의 자식 실험 목록을 칩으로 보여주고, 누르면 그 노드로 이동한다

### 2.3 PR 편집 (P1)

- 패널 안에서 YAML 필드는 폼으로, 본문은 마크다운 에디터로 수정한다.
- 저장하면 호스트 어댑터를 통해 `PATCH /repos/{owner}/{repo}/pulls/{number}`를 호출한다.
- 저장 직전에 PR의 `updated_at`을 비교한다. 다른 사람이 먼저 수정했으면 충돌을 알리고 다시 불러온다.
- YAML 블록 밖의 내용과 알 수 없는 필드는 보존한다.
- "채택(머지)"과 "기각(close)" 버튼은 확인 창을 거친 뒤 실행한다.

### 2.4 새 실험 만들기 (P1)

- 노드에서 "여기서 새 실험"을 누르고 이름과 가설을 입력한다.
- 뷰어가 두 가지를 한 번에 처리한다.
  - 부모 브랜치의 최신 커밋에서 `experiment/<name>` 브랜치를 만든다(`POST /git/refs`).
  - YAML 템플릿이 채워진 Draft PR을 연다.
- 코드 수정은 사용자가 로컬에서 그 브랜치를 받아 이어서 한다.

### 2.5 필터와 레이어 (P1)

- 상태 레이어: running / adopted / rejected를 켜고 끈다.
- "기각된 실험 흐리게" 토글.
- "메트릭으로 색칠": 메트릭 하나를 고르면 노드를 색 스케일로 칠한다.
- 태그와 작성자 필터.

### 2.6 타임라인 재생과 투어 (P1)

- 하단에 PR 생성 시각 기준 타임라인 슬라이더와 재생 버튼을 둔다. 재생하면 초기 구현에서 트리가 자라나는 과정을 애니메이션으로 보여준다.
- 트리 깊이(세대) 단위로 이동하는 네비게이터도 둔다. 로마 앱의 01~14일차 바에 해당한다. 하단 가운데에 화면 너비의 약 1/3로 두고, 넘치는 세대는 가로로 스크롤한다(휠 또는 ‹ › 화살표). 가장자리는 흐려지고, 선택한 세대가 가운데로 오며, "12 / 18"(선택이 없으면 "전체 18") 카운터를 보여준다.
- **투어 모드**(발표용): 루트에서 채택된 경로를 따라 노드마다 N초씩 머물며 가설과 결과를 띄운다. 일시정지, 다음, 머무는 시간, 카메라 속도를 조절할 수 있다.

### 2.7 네비게이션 보조 (P1)

- 미니맵: 전체 트리 개요, 현재 뷰포트, 선택 노드를 보여준다.
- "루트로" / "전체 보기" / "애니메이션 끄기" 버튼.
- 브랜치 이름, 제목, 가설로 검색하고 해당 노드로 이동한다.

### 2.8 3D 연출 확장 (P1)

- 타임라인 재생, 투어 모드와 결합해 시간 순서대로 섬이 자라는 연출을 한다.
- 밤낮 같은 분위기 요소를 검토한다.

### 2.9 research 버전 (P0)

- `research`의 버전 태그(`research/v1`, `research/v2` …, 루트 브랜치 이름이 접두사)를 읽어 본선을 그린다. 접두사 없는 `v1` 같은 태그는 `main`의 릴리스 태그로 보고 무시한다. 첫 버전이 루트이고, 채택되어 research에 머지된 실험 뒤에 다음 버전 마일스톤이 이어진다. 트리는 각 버전에서 다시 뻗어 나간다.
- 돌 기념탑과 깃발로 그린다. 평면 보기에서는 같은 돌을 위에서 본 모습이다. 한 버전에 여러 실험이 합쳐지면 흙길 합류선을 더한다.
- 버전을 누르면 태그 날짜와 커밋, 합쳐진 실험, 버전의 메트릭, 그 버전에서 시작한 실험, 다음 버전, 그 섬의 라벨 메트릭 선택을 보여준다. `research` 고목을 누르면 v1 버전 패널이 열린다.
- 규칙은 [CONVENTIONS.md](CONVENTIONS.md) 1.3과 부모 결정 순서를 따른다.

### 2.10 시간축과 계절 (P0)

- 가로 방향은 이어진 순서다. 부모 → 자식은 날짜와 무관하게 항상 같은 간격(열 1.3개, 새 버전 섬으로 넘어갈 때 1.8개)이고, 가지 줄 사이는 넓게(16) 벌린다. 날짜는 연도·계절 눈금에 쓰며, 눈금은 노드의 (날짜, 위치)를 지나는 단조 변환이라 노드 날짜와 맞는다. 시각은 [CONVENTIONS.md](CONVENTIONS.md)의 시간 결정 순서를 따른다.
- 섬의 풀빛과 꽃·덤불이 그 지점의 계절을 따른다(봄 꽃잎, 여름 짙은 풀, 가을 황금빛, 겨울 눈). 연도 경계에는 연도 칩을 둔다. 평면 보기에서는 땅이 사라지므로 연도 칩으로 해 경계를 보여준다.
- 각 실험의 나무 수관은 브랜치 색이다. 마지막 작업 시각의 계절은 효과로 보여준다. 봄은 나무의 벚꽃과 떨어지는 꽃잎, 여름은 나무 주위를 떠도는 반딧불, 가을은 떨어지는 잎과 텃밭의 낙엽, 겨울은 내리는 눈과 수관의 눈 모자(그루터기와 새싹에도 눈)다. 떨어지거나 떠도는 효과는 모션 줄이기 설정이나 평면 보기에서 멈추고, 꽃·낙엽·눈 모자는 남는다.
- 화면 가운데 지점의 연도와 계절을 레포 정보 카드 바로 아래에 띄운다(연도는 크게, 계절은 작게; 입체·평면 모두). 가로로 이동하면 해가 지나가는 것이 보인다.

## 3. 데이터 갱신

- GitHub API 응답을 캐시하고, ETag 조건부 요청으로 rate limit을 아낀다.
- "새로고침" 버튼을 둔다. P2에서 탭이 활성화될 때 자동으로 갱신하는 기능을 추가한다.

## 4. VS Code 확장 (P1)

- 명령 팔레트의 `ResearchTree: Open Tree`를 실행하면 에디터 탭에 트리 패널이 열린다. 상태 표시줄 버튼으로도 열 수 있다.
- **레포 자동 선택**: 워크스페이스의 git remote(`origin`)로 레포를 정한다. 멀티 루트 워크스페이스에서는 어느 레포를 볼지 고르게 한다.
- **로그인**: VS Code 내장 GitHub 계정을 쓴다. 처음 한 번 "허용"을 누르면 끝이다.
- **확장 전용 기능**
  - 노드에서 "체크아웃"을 누르면 해당 `experiment/*` 브랜치로 로컬에서 전환한다(내장 Git 확장 API 사용).
  - "부모 대비 diff"를 누르면 변경 파일 목록을 보여주고, 파일을 누르면 VS Code diff 에디터로 연다.
  - 현재 체크아웃된 브랜치에 해당하는 노드를 트리에서 강조한다.
  - "새 실험"으로 브랜치와 PR을 만든 뒤 바로 체크아웃한다.
- 외부 링크(GitHub PR, W&B)는 시스템 브라우저로 연다.
- 배포: VS Code Marketplace와 Open VSX. 확장 ID는 `darkpyonix.researchtree`다.

## 5. 로컬 실행: `uv tool` (P1)

셀프 호스팅 방식이다. 중앙 사이트나 인증 프록시를 거치지 않는다.

```bash
uv tool install researchtree   # 설치 (또는 일회성: uvx researchtree serve)
researchtree serve             # localhost에서 뷰어를 띄우고 브라우저를 연다
```

| 명령 | 설명 |
|---|---|
| `researchtree serve [--repo owner/name] [--port N] [--no-browser]` | 로컬 서버를 띄운다. 현재 디렉토리가 git 레포면 그 레포를 기본으로 연다 |
| `researchtree login` / `logout` | 터미널에서 Device Flow로 로그인하거나, 저장된 토큰을 삭제한다. 브라우저 없는 GPU 서버용 |
| `researchtree open` | 현재 레포의 트리를 중앙 웹 뷰어에서 연다 (편의 기능) |

- **최초 로그인**: 로컬 페이지에 처음 접속하면 Device Flow 코드를 보여준다. github.com/login/device에서 승인하면 자동으로 트리 화면으로 넘어간다.
- 서버는 `127.0.0.1`에만 바인딩한다. GitHub 호출은 서버가 대신 하고, 토큰을 브라우저에 넘기지 않는다.
- 사용자 머신에 Node가 필요 없다. 빌드된 SPA가 wheel 안에 들어 있다.

### 5.2 에이전트 기억 (P1)

PR 트리를 타입이 있는 Python 객체로 읽어, 코딩 에이전트가 지난 실험을 코드로 탐색·집계·검사한다. 결정 배경은 [DIRECTION.md](DIRECTION.md) 3.10.

```python
import researchtree as rt

research = rt.load()                         # origin 레포 (또는 "owner/name")
print(research.manifest())                   # 짧은 요약: 섬별 최고 성적, 진행 중, 경고
research.version("v3").describe()            # 섬 하나
e = research["duet-mix"]                     # .hypothesis .metrics .parent .children .conclusion .delta()
e.commits(); e.comments(); e.files()         # 필요할 때 GitHub에서 읽음
research.experiments.where(status="adopted").best("val_loss")
research.check()                             # 규칙 검사 → 경고
```

- 계층: `Research` → `Version`(섬) → `Experiment` → 본문 섹션 → 커밋·코멘트·파일. 요약에서 시작해 필요한 곳만 펼친다.
- `Experiments`는 리스트라 컴프리헨션이 되고, `where`, `sort_by`, `best`, `search`, `table` 도우미가 있다.
- 기본 규칙: 2주 넘게 멈춘 진행 중 실험, 방향을 아는 지표가 하나도 좋아지지 않은 채택(일부만 나빠지면 절충으로 참고 표시), 메트릭 없는 채택, 결론 없는 종료, 본문 경고. 에이전트가 규칙 함수를 직접 넘길 수 있다.
- CLI: `researchtree memory [이름] [--check] [--json]`.
- 트리 규칙은 뷰어와 같다. 공유 픽스처로 두 구현의 결과를 맞춘다.

### 5.3 버전 내기와 브랜치 정리 (P1)

`researchtree release [버전] [--yes]`: 새 버전을 내면서 끝난 실험 브랜치를 정리한다. 규칙은 [CONVENTIONS.md](CONVENTIONS.md) 1.4.

- 옵션 없이 실행하면 계획만 출력한다(삭제 / 보관 머지 / 보류와 이유).
- `--yes`: 작업 트리가 깨끗한지 확인 → `research`를 원격과 맞춤 → 보관 대상 브랜치마다 커밋을 revert하고 `research`에 `--no-ff` 머지(내용이 바뀌지 않았는지 확인) → `<root>/vN` 태그 → `research`, 태그, 보관 브랜치 push → 끝난 브랜치 원격·로컬 삭제.
- 버전 이름을 주지 않으면 마지막 버전의 다음 주 번호를 쓴다.
- 커밋별 revert가 머지 커밋이나 충돌로 실패하면, 브랜치 내용을 갈라진 지점과 같게 만드는 revert 커밋 하나로 대신한다(기록은 지우지 않는다).

### 5.1 학습 스크립트 연동 (P2)

같은 패키지를 학습 프로젝트에 추가해서 현재 브랜치의 PR 본문을 갱신한다.

```python
# uv add researchtree
import researchtree as rt

rt.log(val_loss=2.31, wer=0.184)      # metrics 병합 갱신
rt.set(wandb=run.url)                 # 임의 YAML 필드 설정
rt.conclude("rejected", "수렴이 느림")  # status 설정 + '## 결론' 섹션 작성
```

- 토큰은 `researchtree login`이나 로컬 뷰어에서 로그인할 때 저장한 것을 공유한다. `RESEARCHTREE_TOKEN` 환경변수가 있으면 그것을 우선한다.
- 현재 브랜치가 `experiment/*`가 아니거나 PR을 찾지 못하면 경고만 남긴다. **학습을 중단시키지 않는다.**
- 분산 학습에서는 rank 0에서만 동작한다.
- PR 본문 재작성 규칙은 TS 코어와 같다. 두 구현이 같은 테스트 fixture를 공유한다.
